# Finance Analytics Platform

A simple, deployable finance analytics portfolio application built around the supplied Excel datasets.

## Stack

- Backend: Python, FastAPI, Pandas, SQLAlchemy, Pydantic, psycopg
- Database: PostgreSQL
- Frontend: HTML, CSS, Vanilla JavaScript, Plotly.js
- ETL: Pandas + openpyxl streaming batches
- AI: backend-only LLM HTTP integration

## Dataset
So far
- `customers.xlsx` — 60,000 rows, 12 columns
- `accounts(1).xlsx` — 95,000 rows, 7 columns
- `transactions.xlsx` — 1,048,575 rows, 7 columns

The production API never reads Excel files. Excel is an ETL input only.

## Architecture

## Data model

customers (1) ----< accounts (1) ----< transactions


`customers.customer_id` is the customer primary key. `accounts.customer_id` references it. `transactions.account_id` references accounts.

## Quick start

### 1. PostgreSQL

Create a database and user, then copy `.env.example` to `.env` and update `DATABASE_URL`.

Optional local PostgreSQL with Docker Compose is included, but Docker is not required for deployment.

### 2. Install backend dependencies

```bash
cd backend
python -m venv .venv
# Windows: .venv\\Scripts\\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
```

### 3. Run ETL

From the project root:

```bash
python -m data_pipeline.run_pipeline
```

The pipeline validates and loads customers first, then accounts, then transactions. It uses streaming workbook reads for the large transaction workbook and PostgreSQL COPY for efficient batch loading.

Useful options:

```bash
python -m data_pipeline.run_pipeline --reset
python -m data_pipeline.run_pipeline --validate-only
```

### 4. Start API

```bash
cd backend
uvicorn app.main:app --reload --port 8000
```

Open `http://localhost:8000/docs` for Swagger UI.

### 5. Start frontend

From the `frontend/` directory:

```bash
python -m http.server 5500
```

Open `http://localhost:5500`.

Set `frontend/js/config.js`'s `API_BASE_URL` for a deployed backend.

## API

- `GET /api/health`
- `GET /api/analytics/python/summary`
- `GET /api/analytics/python/monthly-transactions`
- `GET /api/analytics/python/transaction-types`
- `GET /api/analytics/python/channels`
- `GET /api/analytics/python/merchant-categories`
- `GET /api/analytics/python/income-activity`
- `GET /api/analytics/sql/customer-summary`
- `GET /api/analytics/sql/account-summary`
- `GET /api/analytics/sql/transaction-summary`
- `GET /api/analytics/sql/customer-360`
- `POST /api/ai/chat`

Analytics filters are query parameters and are validated by FastAPI/Pydantic.

## AI safety model

FinAI v1 sends a controlled analytics context to the model. It does not execute arbitrary SQL generated by the user. Database credentials and the LLM key remain server-side.

## Testing

```bash
pytest -q
```

Tests cover transformation/validation helpers and basic FastAPI validation behavior. Full integration tests require PostgreSQL populated by the ETL pipeline.

## Deployment

Recommended simple production layout:

```text
Static host (frontend) ----HTTPS----> FastAPI host ----TLS----> Managed PostgreSQL
                                      |
                                      +----> LLM API
```
